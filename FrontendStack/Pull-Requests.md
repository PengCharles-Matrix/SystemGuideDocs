# Pull Request Standard

## Purpose

Pull Requests provide review, automated validation, and controlled integration into main.

## Required process

1. Create a working branch.
2. Implement the change.
3. Run formatting, type checks, tests, and the production build.
4. Commit the completed work.
5. Push the branch.
6. Open a Pull Request.
7. Address review comments.
8. Merge only after required checks and approvals pass.

## PR description should contain

- What changed.
- Why it changed.
- Tests/checks performed.
- Any known limitations or follow-up work.

## Merge rule

A completed feature is not considered integrated until its Pull Request is approved and merged.
